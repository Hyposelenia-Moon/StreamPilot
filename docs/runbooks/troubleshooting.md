# 故障排查（runbooks）

按现象组织。每条都给出"先看什么 → 再做什么"。

日志位置：`%LOCALAPPDATA%\StreamPilot\logs\streampilot-YYYYMMDD.log`（单行 JSON）。
播放页的日志不再显示在画面上：页面的诊断文本以 `log` 消息发给宿主，
写入同一份文件日志，并出现在设置页的「最近事件」里。

---

## 1. 播放页空白 / 一直"等待直播源"

1. 看界面状态行是否出现 `播放器内核尚未就绪`：说明 WebView2 初始化失败。
   - 确认 `Web 目录` 与 exe 同级且包含 `player.html`、`player-core.js`、`mpegts.js`、`hls.js`；
   - 确认已安装 WebView2 运行时（Win10 1803+ 通常自带；缺失时日志会出现 `WebView2` 相关错误）。
2. 看是否出现 `所有候选线路都拒绝了内置播放器的请求`：
   - 平台可能限制了来源（Referer）。确认桥接服务已启动（状态行显示 `桥接：http://127.0.0.1:xxxx`），
     中继会自动为需要 Referer 的流（B站/抖音）加上 Referer；
   - 也可能是候选地址确实过期，点击"解析房间"重新解析。
3. 看状态行是否出现 `已停止自动重试（连续 N 次重新解析都未能出画）`：
   说明该房间的地址反复失效（斗鱼常见）。点「开始播放」手动重试或改用 mpv；
   详见 [斗鱼解析器说明](../parsers/douyu.md) 的「一直重连」一节。

## 1.1 首帧需要点一下画面才开始播放

1. 正常路径不该需要点击：宿主 WebView2 以 `--autoplay-policy=no-user-gesture-required` 启动
   （日志 `播放宿主已初始化` 里带 `autoplayPolicy=no-user-gesture-required`）；
2. 若内核仍要求手势，播放页会走"静音起播 → 立刻恢复音量"的兜底，
   页面日志里会出现 `内核要求静音起播，已恢复音量 30%`；这种情况下**依然不需要点击**；
3. 只有极旧的内核（既不认启动参数、又拒绝静音起播）才会回到"点一下画面"的交互，
   此时页面顶部会给出提示。升级 [WebView2 运行时](https://developer.microsoft.com/microsoft-edge/webview2/) 可解决。

## 1.2 音量不是预期的 30

- 30 只对**首次运行**（或配置里没有 `playback.volume` 字段）生效；
- 程序**不会**强改用户已保存的音量：`%LOCALAPPDATA%\StreamPilot\config.json` 里已有
  `playback.volume` 时按该值生效；
- 需要改成 30：设置页 → 默认音量 → 保存；或退出程序后删除 `config.json` 里的 `volume` 字段再启动。

## 1.3 暂停后画面停住 / 找不到「停止」

- 「暂停播放 / 继续播放」只在**画面下方**（左栏已不再重复提供播放控制）：暂停**不会**结束播放会话，
  播放器、当前地址与缓冲都保留；继续播放会从当前位置恢复，落后直播边缘超过 3 秒时先跳到缓冲末端。
- 暂停期间不会触发"卡顿重连"（页面按 `video.paused` 明确排除），因此暂停再继续不会重连。
- 页面日志不再显示在画面上：页面的诊断文本统一进宿主"最近事件"与日志文件。

## 2. 画面卡顿 / 一顿一顿 / 反复重连

**先看画面下方**（不在设置里）：

1. 「追帧档位」是不是 150/200 ms：数字越小延迟越低、对抖动越敏感。程序**不会**替用户改档位
   （档位入口只有这一处，看到的档位就是生效的档位）；想更稳就手动选 250 ms。
2. 「画质」是不是过高：码率超过带宽时一定卡。换低一档再看。
3. 界面遥测显示 `缓冲 xxx ms · 倍速 x.xx · 丢帧 n`：
   - `倍速 1.08` 说明正在追帧（正常）；`缓冲` 长期偏低并伴随 `丢帧` 持续增长才是真卡；
   - 每条遥测同时以结构化字段落盘（`播放遥测`），字段含 `bufferedAheadMs` /
     `secondsSinceProgress` / `droppedVideoFrames` / `totalVideoFrames` / `extremeTargetMs` /
     `reconnects`。**判断"稳定播放"的取证方式**：同一房间连续播 ≥60 秒，
     在日志里按时间顺序取 6 条以上 `播放遥测`，看 `bufferedAheadMs` 是否长期为正、
     `droppedVideoFrames` 是否基本不增长、`reconnects` 是否保持 0。
4. 仍卡顿请改用「mpv 播放」：mpv 具备更强的缓存与解码容错。

**已知会制造"固定间隔卡顿"的历史原因（均已修）**：
① 候选探测与播放争用同一条直播长连接（现在探测仍在，但不再按耗时重排队，且单候选时跳过探测）；
② mpegts.js 的 `LOADING_COMPLETE`（缓冲取满时也会触发）被当成断流无条件重连；
③ 旧播放器销毁后仍送达的 `ERROR` / `LOADING_COMPLETE` 被算到新会话头上（现在按播放器身份过滤）。
详见 [播放策略](../architecture/playback-strategy.md) 第 4、5 节。

## 3. HEVC 无法播放

现象：提示"该直播流实际为 HEVC（H.265）编码，当前系统不支持 HEVC 解码"。

- 方案 A（推荐）：点击「mpv 播放」，mpv 支持 HEVC 硬解与超分；
- 方案 B：安装 Microsoft 的 HEVC 视频扩展（商店搜索 "HEVC 视频扩展"），随后重新播放；
- 方案 C：重新解析，选择 AVC 编码的候选线路（B站通常同时提供 avc 与 hevc 线路）。

本程序**不会**内置 ffmpeg 软解转码（与"不转码录制"定位冲突，见 [ADR 0005](../adr/0005-bridge-and-packaging.md)）。

## 4. 「mpv 播放」提示未找到 mpv

1. 把 `mpv.exe` 放到 `tools\mpv\mpv.exe`（推荐），或在设置页填写完整路径；
2. 确认设置页保存后状态行显示 `桥接：http://127.0.0.1:xxxx`（mpv 调用走桥接服务）；
3. 若桥接服务未启动：端口 5566 可能被占用。日志会记录 `端口被占用，尝试下一个端口`，
   程序会自动尝试 5566-5575，全部占用时由系统分配；如果连系统端口都失败，检查是否有安全软件拦截。

## 5. 录制没有文件 / 文件很小

1. 看"录制"面板的 `录制中 hh:mm:ss · xx MiB · 分片 n · 重连 n`：
   - 分片序号一直停在 1 且字节很小 → 上游流不稳定，日志会看到 `直播流读取中断`；
2. 检查输出目录是否可写（面板可一键打开输出目录）；
3. 斗鱼房间若只提供 RTMP，录制会直接报"没有可录制（HTTP-FLV / HLS-TS）的候选流"，这是平台限制。

## 6. 录制文件播放异常

- 每个分片独立可播放：分片起始处写入了完整 FLV 文件头 + `onMetaData` + 序列头，时间戳从 0 重定基；
- 若分片仍然异常，检查日志中是否有 `编码参数变化，切分新分片`（主播切分辨率/编码参数属正常切分）；
- 元数据侧车文件 `{主播名}-{房间号}-{开始时间}.meta.json` 记录 `segments` 与实际字节数，可用于核对。

## 7. 解析失败

| 提示 | 含义 | 处理 |
|------|------|------|
| 解析失败：主播未开播（状态：未开播） | 平台明确返回未开播 | 等待开播 |
| 解析失败：主播正在轮播（状态：轮播中） | 平台返回轮播状态 | 本程序不解析重播源 |
| 解析失败：找不到这个直播间 | 房间号/链接错误 | 核对输入 |
| 解析失败：平台拒绝了本次请求（可能触发风控） | 平台风控/非法请求 | 稍后重试；B站可在设置里填 Cookie 提高成功率（禁止绕过风控） |
| 解析失败：网络连接不上平台 | 连接失败/超时/5xx | 检查网络与代理设置 |
| 解析失败：平台返回内容无法识别 | 响应结构变化 | 提交日志中的 `operation` 与 `detail` 字段以便定位 |
| Bigo 要求登录后才能读取直播信息 | Bigo 对匿名/该地区不返回播放信息 | 在设置里填 Bigo Cookie 后重试 |

## 7.1 候选线路全部不可用（能解析但播不出）

页面提示「播放失败：所有线路都连不上」（日志里可看到 `probe-result` / `probe-rejected`）：

1. **先确认主播在播**：解析成功只说明拿到了地址，主播刚下播时地址会立刻失效；
2. **看候选列表**：如果只有 RTMP（斗鱼常见），Web 播放器无法播放，请用 mpv；
3. **本地中继是否工作**：页面只与 `http://127.0.0.1:<端口>/relay/...` 通信，
   桥接未启动时（设置 → 高级 → 「启动程序时自动开启桥接服务」被关掉，或端口被占用）会退化直连并可能被 CORS/混合内容拦下；
4. **HEVC 候选**：系统缺 HEVC 扩展时该候选会被过滤，换画质档位或改用 mpv；
5. 仍失败时，换一个画质档位重试（不同档位的线路/CDN 不同）。

## 7.2 画质下拉里没有最高档

- 高档位（B站 4K/HDR/杜比、抖音原画、虎牙蓝光20M 等）通常要求登录态：在 **设置 → 高级 → 账号与 Cookie**
  填对应平台的 Cookie 后重新解析；
- **画质下拉始终显示**：房间只有一档时会显示当前档位（置灰、不可切换），这是"平台只给了这一档"，不是缺陷；
- 抖音排查：打开 **设置 → 高级 → 记录详细诊断日志**，在日志里搜 `抖音档位诊断`。
  该行列出本次响应里 `options.qualities` / `flv_pull_url` / `hls_pull_url_map` / `stream_url` 直挂的档位键
  与 `hasOrigin`：`hasOrigin=false` 表示平台确实没下发 `origin`（原画档），属平台侧限制；
  `hasOrigin=true` 却没有原画档请附日志反馈（见 [抖音解析器说明](../parsers/douyin.md)）；
- YY 的档位由请求参数 `gear` 决定、官方未公开语义，因此只显示「默认（平台给定）」。

## 8. 代理与网络

- 默认**不使用**系统代理；如需代理，在 `%LOCALAPPDATA%\StreamPilot\config.json` 的
  `network.proxy` 填写（例如 `http://127.0.0.1:10809`），然后重启程序；
- 请求超时默认 8 秒、最多 3 次尝试，可在同一配置的 `network.requestTimeoutSeconds` / `maxAttempts` 调整；
- 中继（`/relay/...`）是**长连接**：只要持续有数据就不计时，连续 30 秒没有新数据才判定断流并断开。

## 9. 需要提交问题时应提供的信息

1. `%LOCALAPPDATA%\StreamPilot\logs\` 中对应时间的日志文件（已自动脱敏 Cookie 与签名参数）；
2. 复现步骤（平台、房间号、追帧档位、画质档位、是否使用 mpv）；
3. 界面状态行与遥测文本。

> 日志中**不含** Cookie、Token 与完整签名 URL（`SensitiveData` 统一脱敏），可安全分享；
> 但 `config.json` 可能包含各平台 Cookie，**不要**分享该文件。
