## 修复「新增预设」在轮播/未开播房间上无法保存

**现象**：新增预设对话框对 `https://live.bilibili.com/1713680379` 报
「解析失败：该直播间正在轮播/重播，本程序不解析重播源。（未保存该预设）」。

**定位**：
- 调 B站 `room/v1/Room/get_info?room_id=1713680379` 实际返回 `live_status=2`（轮播）、`live_time=0000-00-00`，
  解析器判定没错；问题在产品规则——新增预设把"能解析出可播候选"当作保存前提，
  于是未开播/轮播的房间永远无法收藏。
- 轮播在预设开播检查里还会被当成「检查失败」（红字），与"房间有效、只是现在没得看"不符。

**改动**（仅 App 层）：
- `ShellViewModel`：新增 `_presetResolveFailureKind` / `_presetResolvePlatform`；
  `AddPresetFromDialogAsync` 在 `NotLive`/`Replaying` 时仍保存（平台取实际解析平台，输入用规范化后的用户输入）；
  其余失败（RoomNotFound / Network / Rejected / ParseError / InvalidInput）仍拒绝保存。
- 预设开播检查把 `Replaying` 归入「未开播」，不再显示「检查失败」。
- README 第 3 节补充该行为。

**验证**（临时工程 `D:\tmp\preset-harness`，直接构造真实 ShellViewModel，反射调用私有回调）：
- 轮播房间：`error=<null>`、预设 1 条（Sylva摸头妹 / Bilibili / 原链接）、列表项 `Offline`「未开播」。
- 房间不存在：仍返回「解析失败：房间号不存在。（未保存该预设…）」、预设 0 条。
- Release 全解决方案 0 警告 0 错误；C# 204/204；前端 81/81。
