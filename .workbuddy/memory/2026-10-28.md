## 修复「新增预设」在轮播/未开播房间上无法保存

**现象**：新增预设对话框对 `https://live.bilibili.com/1713680379` 报
「解析失败：该直播间正在轮播/重播，本程序不解析重播源。（未保存该预设）」。

**定位**：
- 调 B站 `room/v1/Room/get_info?room_id=1713680379` 实际返回 `live_status=2`（轮播）、`live_time=0000-00-00`，
  解析器判定没错；问题在产品规则——新增预设把"能解析出可播候选"当作保存前提，
  于是未开播/轮播的房间永远无法收藏。
- 轮播在预设开播检查里还会被当成「检查失败」（红字），与"房间有效、只是现在没得看"不符。

**改动**（仅 App 层）：
- `ShellViewModel`：新增 `_presetResolveFailureKind` / `_presetResolvePlatform`；
  `AddPresetFromDialogAsync` 在 `NotLive`/`Replaying` 时仍保存（平台取实际解析平台，输入用规范化后的用户输入）；
  其余失败（RoomNotFound / Network / Rejected / ParseError / InvalidInput）仍拒绝保存。
- 预设开播检查把 `Replaying` 归入「未开播」，不再显示「检查失败」。
- README 第 3 节补充该行为。

**验证**（临时工程 `D:\tmp\preset-harness`，直接构造真实 ShellViewModel，反射调用私有回调）：
- 轮播房间：`error=<null>`、预设 1 条（Sylva摸头妹 / Bilibili / 原链接）、列表项 `Offline`「未开播」。
- 房间不存在：仍返回「解析失败：房间号不存在。（未保存该预设…）」、预设 0 条。
- Release 全解决方案 0 警告 0 错误；C# 204/204；前端 81/81。

## HDR 录制对比与首分片头缺陷修复

**对照对象**：`D:\Downloads\BililiveRecorder_video\1875093303-轻漣`（BR 2.20.0 录制）。
实测参数：HEVC Main10 1920x1080 60fps 15360 kbps + AAC 328 kbps，
`primaries=bt.2020 / gamma=pq / max-luma=1000`（HDR10/PQ，非 HLG）。

**复现方式**：截取参考录像前 60 秒（90.4 MB），用进程内 TCP HTTP 服务回放给本插件
`RecordingSession`（FlvHttp/HEVC 候选、MaxBytes=64MiB），主动停止后比对产物。

**发现（已修）**：B 站 HDR 的 FLV 标签顺序是 `script → 音频序列头 → 视频序列头`。
旧实现用音频头创建分片，随后到达的视频头既不写入也不补写，首分片缺少 hvcC；
mpv 报 `extract_extradata: No start code is found`，整段无法解码。onMetaData 也因
"写入器尚未创建"被永久丢弃（后续分片同样没有）。
- 修复：`SessionState.ScriptTag` 会话级保存；`EnsureWriterAsync` 返回是否新建；
  写入器已存在时补写晚到的序列头（音/视先到都覆盖）。
- 回归：`FlvStreamRecorderTests` 新增 3 条（音频先到 / 视频先到 / 切分后的新分片）。

**修复后复测**：两个分片均被 mpv 识别为 `hevc [Main 10] 1920x1080 60fps 15360 kbps`、
`bt.2020/pq/1000`，首个关键帧载荷 SHA256 与源文件一致（逐字节未改）。
C# 207/207，前端 81/81。

**遗留（未改）**：录制候选按 API 顺序取第一条（1713680379 实测 4 条全 AVC）。
HDR 房间若同时返回 AVC/HEVC，可能录到 SDR；需给候选加 HDR 标记并定义选取策略（待确认）。

**另**：用户"实测未生效"的截图文案（"该直播间当前未开播。" / "本程序不解析重播源。"）
与 v0.2.0 的字符串完全一致，说明当时运行的是旧 exe；v0.2.1 已含预设修复。
当前 v0.2.1 发布包不含本轮 HDR 修复，需重新打包才能生效。
